> 高级软件工程综合大作业 · 第 3 组

## 项目简介

本仓库为智能体开发平台的**原型系统**，用于大作业「原型系统及演示视频」部分。

### 已实现的功能细节

**登录模块**
- 表单校验、验证码校验（点击刷新，校验失败自动换一张）、记住账号、加载态、错误提示
- 登录态持久化到 localStorage，路由守卫拦截未登录访问

**智能体管理模块**
- 关键字搜索（名称/简介）、按状态与分类筛选、条件重置，查询条件由 Pinia 统一管理
- 卡片展示：图标、名称、分类、状态标签、基座模型、创造性参数、对话数、最近更新时间
- 新建/编辑弹窗：名称、图标、分类、简介、基座模型、创造性滑块、提示词、发布状态，含表单校验
- 列表操作：发布/下线（二次确认）、复制为新草稿、删除（二次确认）、翻页（删除后自动回退空页）
- 数据通过 localStorage 模拟持久化，刷新页面不丢失

**对话调试模块**
- 左侧智能体列表（搜索、状态指示点），右侧对话区，从智能体卡片「调试」按钮可带参跳转并自动选中
- 流式输出：回复逐字推送 + 光标闪烁动画，生成中可点击「停止生成」中断
- 每个智能体拥有独立会话，切换后各自保留上下文；头部实时显示对话轮次
- Enter 发送、Shift + Enter 换行，生成中禁用输入；新消息自动滚动到底部
- 新会话提供按分类定制的推荐提问，一键发送
- 可查看当前智能体的系统提示词，支持一键清空会话
- 回复由 `src/api/chat.js` 的模拟引擎按智能体分类生成，接入真实模型时替换为 SSE / WebSocket 即可

**知识库模块**
- 知识库列表：按名称/描述搜索、按群组筛选，卡片展示文档数与切片数、向量模型、更新时间
- 新建知识库：名称、描述、群组、向量模型（内置 bge-large-zh / 阿里云 text-embedding-v3 / 第三方 m3e-base）、切片策略（默认切分 / 自定义切片 / 整文件切片）
- 文档管理：支持 doc、docx、txt、pdf、ppt、pptx、md、wps、ofd 格式；上传后状态由「解析中」自动流转为「已就绪」并生成切片
- 解析清洗策略可配置：文字提取、图片文字识别（OCR）、版面分析、文档图片解析；支持简历、PPT 幻灯片、论文、结构化问答对等导入模板
- 文档标签编辑、文档删除（连同其切片一并删除）
- **切片查看与原文定位**：左侧切片列表（序号、token 数），点击任一叶切片，右侧原文自动高亮该切片对应的字符区间，并显示「已定位到第 N 个切片（第 X–Y 字符）」
- **命中测试**：输入自然语言问题，在知识库范围内检索最相关切片，返回相似度排序结果；支持滑动条调节召回数量（TopK）与匹配分阈值；每条结果可一键跳回原文高亮位置，便于直观验收检索效果
- 检索打分由 `src/api/knowledge.js` 的字符 2-gram 重合度模拟，接入真实向量检索时替换该函数即可

**模型市场模块**
- 模型广场：预置 Qwen、Ernie、DeepSeek、GLM、Llama 等主流大模型，以及内置 embedding 与 rerank 排序模型；支持按模型类型（大语言模型 / 向量模型 / 排序模型）、来源（平台预置 / 第三方接入）、服务状态筛选与关键字搜索
- **接入第三方模型**：按标准 OpenAPI 规范填写接口规范、接入协议（HTTP / WebSocket / gRPC）、接口地址、API Key、上下文长度、TPS 超分比例；**显示名称支持自定义**；接入前可做连通性测试，成功时返回服务响应耗时
- 服务管理：服务上线 / 下线 / 重启，调整 TPS 超分比例；下线后的模型会自动从智能体与知识库的可选模型中移除
- 版本管理：多版本列表、切换当前版本（切换后自动重新上线）、新增版本
- 评估指标：自动规则评估得分；人工评估维度可由用户自定义增删（最多 5 个），系统按维度自动计算平均分与正向示例占比
- **多模型同步比对测试**：同一个问题并行发给 2~4 个已上线的大语言模型，并排流式展示回答，可对比回答内容、响应耗时与 Token 消耗
- 模型市场是平台内模型信息的**唯一来源**：`src/views/agents` 的基座模型下拉读取已上线的语言模型，`src/views/knowledge` 的向量模型下拉读取已上线的向量模型，均通过 `src/api/model.js` 的 `llmOptions()` / `embeddingOptions()` / `modelLabel()` 获取

**工作流编排模块**
- 工作流列表：按名称/说明搜索、按状态（已发布 / 草稿 / 已下线）筛选，卡片展示节点数、运行次数与发布范围；支持编排、复制、导出 JSON、发布/下线、删除
- **可视化画布编排**：左侧节点面板拖拽（或双击）添加节点，拖动节点调整位置（10px 网格吸附），从输出端口拖到输入端口建立连线，滚轮以光标为锚点缩放、空白处拖动平移、「适应画布」自动取景
- **19 类节点**，覆盖招标书要求的全部节点类型：
  - 基础节点：开始、大模型、知识库、智能体、结束
  - 工具节点：组件、API 调用、**MCP Server**、代码、数据库、文本处理、query 多轮改写
  - 逻辑节点：意图识别（3 路分支）、条件分支、循环、跳转、信息收集、记忆、流式输出
- 节点配置面板：按节点类型动态渲染配置项，类型包括文本、多行文本、代码、下拉、数值、滑块、变量列表与 MCP 工具列表；大模型下拉读取模型市场已上线的语言模型，知识库下拉读取已有知识库，智能体下拉只列出已发布的智能体
- **MCP Server 节点**：支持 MCP-SSE / MCP-stdio 两种传输方式，填写 Server 地址后可「连接并获取工具」，拉取到工具列表后逐个勾选本次调用要用的工具；连接失败时给出明确原因（地址格式错误 / 无法连接）
- **连线合法性校验**：拒绝重复连线、自连与成环连线，并即时提示原因；开始节点只能有一个且不能作为终点
- **试运行**：按拓扑序依次执行节点，右侧抽屉实时刷新执行轨迹（序号、节点名、耗时、输出），画布上同步高亮「正在执行 / 已完成」节点并把走过的连线标绿；每条轨迹可「在画布中定位」，运行结束后给出最终输出与总耗时
- **保存与发布**：保存前校验缺少开始节点、存在环路、节点没有上游连线三类问题并阻止落盘；发布需先保存成功，支持个人 / 组织 / 公开三种发布范围；复制工作流会重新生成节点与连线 id，导出为 JSON 便于在团队间传递

## 技术栈

- **Vue 3**（Composition API + `<script setup>`）
- **Vite 7** 构建工具
- **Element Plus** 组件库
- **Vue Router 4**（hash 模式路由）
- **Pinia** 状态管理

后端接口目前为**前端 Mock 实现**（`src/api/` 目录），后续接入真实后端时仅需替换该目录下的文件，页面与状态管理代码无需改动。

## 快速开始

环境要求：Node.js ≥ 20.19

```bash
# 1. 安装依赖（首次）
npm install

# 2. 启动开发服务器
npm run dev
# 浏览器访问 http://localhost:5173

# 3. 打包生产版本（用于部署/演示）
npm run build && npm run preview
```

## GitHub 协作规范

### 分支模型

- `main`：主分支，只接受经过审查的合并（设置为保护分支）
- `feature/<模块名>`：功能分支，如 `feature/login`、`feature/agent-list`
- `fix/<问题描述>`：修复分支

### 提交规范（Conventional Commits）

```
feat: 新增登录页面
fix: 修复验证码刷新失败问题
docs: 更新 README
style: 调整登录页样式
refactor: 重构认证状态管理
```

### 协作流程

1. 每次开发前：`git pull` 拉取最新代码
2. 新建分支：`git checkout -b feature/你的模块`
3. 开发并提交（小步提交，一个提交只做一件事）
4. 推送分支：`git push -u origin feature/你的模块`
5. 在 GitHub 上发起 **Pull Request**，由组员 Code Review 后合并到 `main`
6. **禁止直接 push 到 `main`**

### 合并冲突处理

提交前先 `git pull origin main` 并解决冲突；拿不准时在群里沟通，不要强制覆盖（`git push -f` 禁用）。
